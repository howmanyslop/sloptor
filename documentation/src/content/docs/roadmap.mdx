sloptor is a native Go reimplementation of the roblox-ts compiler (`rbxtsc`), built on
[typescript-go](https://github.com/microsoft/typescript-go). The contract is upstream
parity on unaffected surfaces, with the verified `@isentinel/roblox-ts@4.0.11` fork
archive authoritative for fork-changed surfaces. The same `@rbxts/*` ecosystem and CLI
remain the target, at roughly 10x the speed.

- **Design spec:** `docs/superpowers/specs/2026-06-05-rotor-design.md`
- **Detailed plans:** `docs/superpowers/plans/`
- **Porting source of truth:** research digests in `docs/superpowers/research/` (authority order: `reference/` > digest > plan > tests)
- **Acceptance test:** the real `randomness` game project follows the applicable upstream or fork-authoritative oracle for each surface

Legend: ✅ done · 🚧 in progress · ⬜ not started

### Fork parity boundary (July 2026)

The committed `roblox-ts.zip` archive is the authority for surfaces changed by the
`@isentinel/roblox-ts@4.0.11` fork: varargs optimization, object-rest direct access,
the `rbxts` option cascade, `.luau.map` source maps, the copy-files gate, the Rojo
resolver cache, solution builds, and solution watch. The older `reference/roblox-ts`
tree remains the upstream parity reference for unaffected code only. User-facing
schema and help must describe the fork behavior without presenting upstream-only
diagnostic names or cache layouts as sloptor contracts.

The project layer also publishes these generated build-state boundaries: `rbxts.copyfiles.json`
in `outDir`, the fork-compatible `rbxts.rojocache.json` name protected from cleanup,
`.rotor/cache/rojo/` for sloptor's hashed resolver state, adjacent `.luau.map` files when
source maps are enabled, and `*.rbxtsc.tsbuildinfo` for sloptor incremental state.
`RBXTSC_WRITE_CONCURRENCY`, `ROTOR_WRITE_WORKERS`,
and `UV_THREADPOOL_SIZE` are documented tuning and cleanup
controls, not tsconfig options.

## Post-v1 Follow-up

**Watch v2 + QOL + hardening (June 11, 2026; spec: `docs/superpowers/specs/2026-06-11-rotor-watch-v2-qol-design.md`):**

- [x] **Watch engine v2** — pruned snapshot walks (`os.ReadDir` + `entry.Info()`; `node_modules`, dot-dirs, and the build-written `out`/`include` trees never walked — v1 stat'ed every `node_modules` file every 250 ms), editor-junk ignore (vim swap/backup probes, emacs locks, `.DS_Store`, `Thumbs.db`), debounced batch rebuilds (50 ms quiet timer, 500 ms cap — a "save all" burst lands as one rebuild reporting every file), pre-build baseline snapshots (fixes the v1 lost-update bug where a save during a build was silently absorbed), adaptive poll cadence (10× walk cost, clamped 100 ms–1 s; v1 was a fixed 250 ms). Applies to both `build -w` and `check -w`. Smoke-verified end to end: 43-file fixture, single-file edit → 1-file incremental rebuild in 64 ms
- [x] **Watch/CLI logging QOL** — batched change lines (`3 files changed · a.ts, b.ts, +1 more`), rebuild counter, last-build duration, and a build-time history sparkline (`term.Spark`, interactive terminals only) on the idle line
- [x] **Security hardening** — output-path containment guard (`filepath.IsLocal` on every compiled output's project-relative path before writing), sidecar cache extraction tightened to `0o700`/`0o600`, and a `vuln` CI job running pinned `govulncheck@v1.3.0 ./...` (validated locally: "No vulnerabilities found")
- [x] **`$getModuleTree` folder support (June 12, 2026 — sloptor extension, first deliberate superset of rbxtsc)** — upstream requires the macro's specifier to resolve as a module (a folder needs `index.ts`; upstream declared folder support "more work than worth it"). sloptor now resolves folder specifiers directly (`getFolderImportParts` in `internal/transformer/importexpr.go`): relative specifiers against the importing file's dir, non-relative through tsconfig `paths` (covers the baseUrl rewrite) then project-root-relative (`"src/shared/systems"` style). Regular imports unchanged — only `$getModuleTree` opts in; everything that compiles under rbxtsc stays byte-identical. End-to-end fixture `internal/compile/testdata/gmtree_folder_model` pins all three specifier forms; verified the real-world failing case (baseUrl `src` + `$getModuleTree("src/shared/systems")`, no index.ts) compiles and rbxtsc 3.0.0 rejects it
- [x] **Loop label support (August 6, 2026 — sloptor extension, second deliberate superset of rbxtsc after `$getModuleTree` folders)** — rbxtsc 3.0.0 bans every labeled statement (`noLabeledStatement`); sloptor compiles `outer: for (...) { break outer; continue outer; }`. Luau has neither labels nor `goto`, so a label that a plain `break`/`continue` cannot satisfy lowers to a `"none" | "break" | "continue"` flag temp plus unwinding checks after each enclosing break boundary (`internal/transformer/labeledstatement.go` + `State.LabelChecks`/`LabelResets`). Design follows roblox-ts PR [#2928](https://github.com/roblox-ts/roblox-ts/pull/2928) but fixes five defects in it locally: the depth/index heuristic that breaks an _unlabeled_ enclosing loop, `switch` not counted as a break boundary (sloptor lowers it to `repeat ... until true`, which a bare `break` exits), labeled non-loop statements emitting a bare `break`, no function/`try` barrier (a check inside a closure would break the wrong loop), and only the first of two labels on one loop getting a continue check. Rejected with clear diagnostics rather than wrong output: labels crossing `try`/`catch` (`noLabeledStatementsWithinTryCatch`, message byte-exact with the PR), unknown labels behind `// @ts-ignore` (`rotorUnknownLabel`), a labeled non-loop statement whose body also holds an unlabeled `break`/`continue` bound to an enclosing loop (`rotorLabeledStatementFlowControl`), and a labeled `continue` targeting a `do`/`while` whose condition needs temporaries (`rotorLabeledContinueInDoWhile` — Luau forbids `continue` before those locals; the identical _unlabeled_ hole is an rbxtsc bug sloptor reproduces for parity). Byte parity is untouched: no label program compiles under rbxtsc, so `testdata/diff` and `testdata/conformance` goldens are unchanged. Pinned by `internal/transformer/labels_test.go` (authored expectations, not rbxtsc-derived), the rotor-owned Lune spec `testdata/conformance/rotor/label.spec.ts` (21 runtime cases), and the end-to-end fixture `internal/compile/testdata/labels_model`
- [x] **`--!native` type annotations (October 29, 2026 — sloptor extension, emitted Luau differs from rbxtsc)** — opt-in via `"rbxts": { "nativeTypes": true }` in tsconfig.json or `nativeTypes = true` in rotor.toml (tsconfig wins when both are set; default off, where `//!native` files compile exactly like rbxtsc). When enabled, a file whose leading comments include `//!native` now emits Luau parameter and return annotations taken from the TypeScript types (`number`, `string`, `vector`/`Vector3`, and table types spelled structurally: `{ T }` for arrays, `{ A | B }` for tuples, `{ [K]: V }` for `Map`/`Record`/index signatures, `{ [K]: true }` for `Set`, and `{ a: number, b: string? }` for anonymous object types, followed into nested members), so Luau's native compiler can specialize those parameters. A named interface or non-generic object type alias is emitted once as a Luau `type Node<K, V> = { ... }` (readonly dropped, optional members `T?`, self references kept), at the declaration when that declaration is a top-level statement of the file and hoisted next to the header otherwise (a namespace-, function-, or block-scoped declaration, or one imported from another module); a merged interface emits one alias, at its first declaration, with every merged member. String and boolean literal types mirror as Luau singletons (`there: "there"`, `flag: true`, with `true | false` spelled `boolean`), while an enum member and a number literal stay `string`/`number`; a top-level parameter keeps its `"a" | "b"` annotation, which Luau's compiler tags `string`, but a boolean literal there stays unannotated like `boolean`. Function types are spelled `(key: K, other: T?) -> V`, `void` returns `()`, a function's own type parameters are declared (`local function f<K, V>(`), and nested positions mirror `boolean` and allowlisted Roblox types by name. Top-level parameters are what Luau tags, so their policy is narrower: `boolean`, Roblox types/`Instance`s, class instances, mixed unions, and a bare generic from an _enclosing_ function stay unannotated (an outer generic would be tagged userdata and fail the native entry guard on every call). A shape that cannot be written out (deeper than four levels or two index signatures) falls back to `{ [any]: any }`. Files without the directive are byte-identical to rbxtsc, and a bare `table` is never emitted because Luau's compiler would tag it userdata and the native entry guard would fail on every call
