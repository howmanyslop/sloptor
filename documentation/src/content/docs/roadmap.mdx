sloptor is a native reimplementation of the roblox-ts compiler (`rbxtsc`). It builds on
[tsrs](https://github.com/oxc-project/tsrs), a Rust port of [typescript-go](https://github.com/microsoft/typescript-go).
It began in Go. The Rust port in `crates/` replaced that code, and the Go code no longer
exists. The phase records below are history. They still name the Go packages and tools of
their day. The contract is upstream parity on code paths the fork leaves alone. The verified
`@isentinel/roblox-ts@4.0.11` fork archive is the authority for code paths the fork changed.
sloptor still targets the same `@rbxts/*` ecosystem and command-line tool, at about 10x the
speed.

- **Design spec:** `docs/superpowers/specs/2026-06-05-rotor-design.md`
- **Detailed plans:** `docs/superpowers/plans/`
- **Porting source of truth:** research digests in `docs/superpowers/research/`, ordered by authority from `reference/` down through digest and plan to tests
- **Acceptance test:** the real `randomness` game project follows the applicable upstream or fork-authoritative oracle for each feature area

Legend: ✅ done · 🚧 in progress · ⬜ not started

## Phase 4, project layer ✅

_Plan: `docs/superpowers/plans/2026-06-07-rotor-phase4.md`. Digest: `phase4-project-digest.md`.
These changes turn sloptor from a compile library into a usable command-line tool._

- [x] Full emit layout. It writes the `out/` tree and translates `index.*` to `init.*`. The cleanup and copyFiles passes went into the Phase 4 output pipeline. Output selection between `.lua` and `.luau` arrived with `--luau`, and `include/` emission came earlier in 3c through `internal/includefiles` and `--noInclude` and `--includePath`.
- [x] `.d.ts` emit for declaration builds. Package projects now emit declarations through the tsgo declaration pass, and sloptor's write callback handles the `types="types"` rewrite.
- [x] Full `rbxtsc` command-line flag surface. Phase 4 Task 1 added the ProjectOptions merge, where defaults come before the tsconfig `rbxts` key and argv comes last. Absent command-line booleans don't clobber `rbxts` values. The task also added `-p/--project` with a path and an upward tsconfig search. `--rojo` treats an empty string as a fall through to discovery, with the quirk kept verbatim. Next came `--luau`, `--logTruthyChanges`, `--optimizedLoops` with the transformer gate wired, and `--writeOnlyChanged`. That last flag shipped a command-level byte compare, which later moved into the compile write phase. `--verbose` gained a `LogService` analog in `internal/logservice`. It adds a yellow `Compiler Warning:` channel that now carries the Rojo resolver warnings dropped before, along with partial-line tracking and upstream benchmark and progress line formats. The task closed with `--version` and `--allowCommentDirectives`. Usage errors now exit 1 for rbxtsc parity, where they used to exit 2. `--writeTransformedFiles` parses but waits. It warns that the feature isn't supported yet, and it sits out of v1. Comment-directive hoisting of `--!strict` at the top of the file already worked in `transformer/sourcefile.go`. `build`, `--type`, `-w`, and `--usePolling` came in 3c and 4.
- [x] Watch mode v1. `sloptor build -w` arrived with polling rebuilds, and `--usePolling` semantics run all the time today. Each build reuses the manifest-backed changed-file selection path. Watch v2 superseded it on June 11, 2026, as the Post-v1 follow-up notes: pruned snapshots from `os.ReadDir`, debounced batch rebuilds, mid-build edit detection, and an adaptive 100 ms cadence.
- [x] Incremental builds with a tsbuildinfo equivalent. sloptor now writes its own manifest at the configured buildinfo path and recompiles only changed `.ts` and `.tsx` files plus transitive importers. Declaration emit follows the same selected set. A build that breaks doesn't advance the manifest.
- [x] Transformer-plugin Node sidecar integration. Plugin-configured compiles and builds run the worker from `tools/sidecar`, log `transformer-not-found` as a warning, hard-fail when Node is missing, and recompile and render from an overlay-backed tsgo Program. The June 10, 2026 hardening **embedded the worker in the binary**. The worker extracts to a content-addressed user-cache dir, and `ROTOR_SIDECAR_PATH` overrides that path. It resolves **typescript from the project's node_modules**, the same instance plugins require and upstream's shared-instance guarantee. Plugin `console.log` output now goes to its own channel, away from the stdout protocol. sloptor also keeps **one warm worker per project across builds and `-w` rebuilds** with stamp-diffed `changedFiles` overlays. The test suite proves this against real `rbxts-transformer-flamework@1.3.2` and `rbxts-transform-env@3.0.0` in `testdata/transformers/project`, asserting identifier metadata, `Flamework.addPaths` rojo rewriting, and env inlining. Note that `@rbxts/transform-env` does not exist on npm, and the real package is `rbxts-transform-env`. The known limitation is that a warm worker's plugin-visible view of an edited ambient `.d.ts` can be stale until the watch session restarts. sloptor's own typecheck doesn't see that staleness.
- [x] A full `validateCompilerOptions` port, which arrived in 3c with byte-exact diagnostic texts. One known gap: sloptor reads enforced options that appear only in an `extends` parent from the root, which matches the sanitizer gap. Fixing it needs extends-chain resolution here.
- [x] Concurrency. `GetTypeCheckerForFile` restores checker-affined project compilation. `CompileProject` and `CompileFile` no longer assume checker 0. Project compilation now runs one transform worker per checker group with a per-checker `MultiState`, and the tsgo checker pool no longer pins to one checker.
- [x] **Performance, filesystem-stat caching.** This builds on the checker-group parallelism preceding and keeps output byte-identical. On the 95-file acceptance project, a full `sloptor build` went from **545 ms to 355 ms**. An incremental no-op rebuild, the watch case, went from **369 ms to 180 ms, about 2×**:
    - **`cachedvfs` host FS.** It wraps the compiler host for build and `sloptor check`, so module resolution's repeated `Stat`, `FileExists`, `Realpath`, and `DirectoryExists` probes get memoized for the pass. Those probes took about 40% of warm time in `GetFileAttributesEx` system calls, since every checker group otherwise re-stats the same `node_modules/@rbxts` paths. A build never mutates its source tree mid-pass, so this is safe. tsgo's own project host uses the same wrapper.
    - **Rojo `searchDirectory`.** It reads `os.ReadDir` entry kinds instead of calling `os.Stat` twice per child. Only reparse points, such as junctions and symlinks, fall back to a following stat, which keeps pnpm installs correct.
- [x] **Command-line logging and developer experience.** A new `internal/term` color and style layer respects NO_COLOR and FORCE_COLOR, enables VT on Windows, and falls back to ASCII glyphs. `cmd/rotor/ui.go` gives `build`, `check`, and `watch` clean output: a banner, ✓ and ✗ result blocks, throughput, failures in color, and watch change and idle lines. `internal/logservice` held byte-stable for the differential tests. One-shot diagnostics support CPU, trace, block, mutex, heap, and timing output. Finite diagnostics don't accept watch mode.
- [x] V1 cleanup triage. The remaining cleanup outside the main feature set, removing the `TransformStatement` func-var, goes to post-v1 engineering follow-up instead of blocking parity. Warmer sidecar watch sessions arrived June 10, 2026.
- [x] Known cleanup: trailing-comment handling for a block `}` in `getLastToken`.

### Fork parity boundary, July 2026

The committed `roblox-ts.zip` archive is the authority for features the
`@isentinel/roblox-ts@4.0.11` fork changed: varargs optimization, object-rest direct access,
the `rbxts` option cascade, `.luau.map` source maps, the copy-files gate, the Rojo
resolver cache, solution builds, and solution watch. The older `reference/roblox-ts`
tree covers only unaffected code as the upstream parity reference. User-facing
schema and help must describe the fork behavior without presenting upstream-only
diagnostic names or cache layouts as sloptor contracts.

The project layer also publishes these generated build-state paths: `rbxts.copyfiles.json`
in `outDir`, the fork-compatible `rbxts.rojocache.json` name that cleanup protects,
`.rotor/cache/rojo/` for sloptor's hashed resolver state, adjacent `.luau.map` files when
source maps are enabled, and `*.rbxtsc.tsbuildinfo` for sloptor incremental state. The docs
describe `RBXTSC_WRITE_CONCURRENCY`, `ROTOR_WRITE_WORKERS`, and `UV_THREADPOOL_SIZE` as
tuning and cleanup controls, not tsconfig options.

## Version 1.0, drop-in replacement ✅

Local verification on June 7, 2026 used:

- `go test ./... -count=1`
- `go test ./internal/conformance -count=1` with `ROTOR_ROJO_PATH`, `ROTOR_LUNE_PATH`, and `ROTOR_RANDOMNESS_PATH`
- `bun test` in `tools/sidecar`, after `bun install --no-save`. `npm test` still works as a fallback.
- `go test ./internal/compile -run TestTransformersFixture -count=1` for real-package transformer coverage of Flamework and rbxts-transform-env. It needs `bun install --no-save` in `testdata/transformers/project`.

CI has covered this continuously since June 8, 2026. `.github/workflows/ci.yml` runs gofmt,
`go vet`, `go build ./...`, and the full `go test ./...` on every push to `master` and every
PR. It uses the shared `.github/actions/setup` composite action, which provisions Go,
**Bun**, and Node for the transformer sidecar. Bun is the canonical fixture installer, and
the npm fallback caused flaky installs. CI also runs the sidecar JS suite through
`node --test` in `tools/sidecar` and installs `testdata/transformers/project` so the
real-package transformer test runs. CI and `release.yml` set
`ROTOR_REQUIRE_TRANSFORMERS_FIXTURE=1`, so a missing fixture install breaks the run instead of
skipping the real-package test without a word. rojo and lune are intentionally absent from
CI, so the lune runtime suite skips there. That suite runs locally through `aftman install`,
and the byte-parity differential and diagnostics tests exercise it either way. `release.yml`
reuses the same setup, runs the tests, and then publishes command-line binaries through
`GoReleaser`.

Linux validation ran on June 10, 2026 in a golang:1.26-bookworm container with Node 22 and
npm installs from a clean clone. It covered the sidecar JS suite, `go vet`, the full
`go test ./...`, and the sidecar and transformer tests under `-race`. It also ran a
release-style `sloptor build` of the transformers fixture with
`CGO_ENABLED=0 -trimpath -ldflags "-s -w -X main.version=..."`, including extraction of the
embedded sidecar to `~/.cache/rotor`. Everything passed. All six `GoReleaser` targets
cross-compile, and `goreleaser check` validates the config. Note that releases up to
**v1.0.2 predate the embedded sidecar**. Their transformer-plugin support only worked from a
repo checkout, and the first release after June 10, 2026 carries the fix.

Success criteria from the design spec:

1. Output identical byte for byte to rbxtsc 3.0.0, after header normalization, on the upstream corpus and `randomness`
2. The vendored behavioral suite passes under Lune, and the vendored diagnostics corpus matches upstream expectations
3. `sloptor build` and `sloptor build -w` work as drop-in `rbxtsc` replacements with the same npm packages
4. Measured wins: ≥5x cold build, near-instant watch rebuilds

**Out of scope for v1:** the playground and `VirtualProject`, `--writeTransformedFiles`, and `devlink`

## Post-v1 follow-up

**Watch v2, quality of life, and hardening, June 11, 2026.** Spec: `docs/superpowers/specs/2026-06-11-rotor-watch-v2-qol-design.md`.

- [x] **Watch engine v2.** It prunes the snapshot walks. `os.ReadDir` and `entry.Info()` skip `node_modules`, dot-dirs, and the build-written `out` and `include` trees. v1 called stat on every `node_modules` file every 250 ms. It ignores editor junk: vim swap and backup probes, emacs locks, `.DS_Store`, and `Thumbs.db`. It debounces batch rebuilds with a 50 ms quiet timer and a 500 ms cap, so a "save all" burst becomes one rebuild that reports every file. Baseline snapshots run before each build, which fixes the v1 lost-update bug where a save during a build disappeared without a trace. The poll cadence adapts at 10× the walk cost, clamped between 100 ms and 1 s, where v1 used a fixed 250 ms. This applies to both `build -w` and `check -w`. A smoke test verified it end to end: a 43-file fixture rebuilt one file in 64 ms after a single-file edit.
- [x] **Watch and command-line logging quality of life.** Batched change lines such as `3 files changed · a.ts, b.ts, +1 more`, a rebuild counter, the last-build duration, and a build-time history sparkline from `term.Spark` on interactive terminals only, all on the idle line.
- [x] **Security hardening.** An output-path containment guard calls `filepath.IsLocal` on every compiled output's project-relative path before writing. Sidecar cache extraction is tightened to `0o700` and `0o600`. A `vuln` CI job runs pinned `govulncheck@v1.3.0 ./...`, and local validation found zero vulnerabilities.
- [x] **`$getModuleTree` folder support, June 12, 2026. A sloptor extension and the first deliberate superset of rbxtsc.** Upstream requires the macro's specifier to resolve as a module, so a folder needs `index.ts`, and upstream called folder support too expensive to build. sloptor now resolves folder specifiers directly through `getFolderImportParts` in `internal/transformer/importexpr.go`. It resolves relative specifiers against the importing file's dir, and non-relative specifiers through tsconfig `paths` first, which covers the `baseUrl` rewrite, then relative to the project root in the `"src/shared/systems"` style. Regular imports are unchanged, and only `$getModuleTree` opts in, so everything that compiles under rbxtsc stays byte-identical. The end-to-end fixture `internal/compile/testdata/gmtree_folder_model` pins all three specifier forms. The real-world case that used to break now compiles: `baseUrl` set to `src` with `$getModuleTree("src/shared/systems")` and a folder that holds no `index.ts`. rbxtsc 3.0.0 still turns that case down.
- [x] **Loop label support, August 6, 2026. A sloptor extension and the second deliberate superset of rbxtsc after `$getModuleTree` folders.** rbxtsc 3.0.0 bans every labeled statement through `noLabeledStatement`. sloptor compiles `outer: for (...) { break outer; continue outer; }`. Luau has neither labels nor `goto`. A plain `break` or `continue` can't satisfy every label, so the rest lower to a `"none" | "break" | "continue"` flag temp, with unwinding checks after each enclosing break boundary. That work lives in `internal/transformer/labeledstatement.go` with `State.LabelChecks` and `LabelResets`. The design follows roblox-ts PR [#2928](https://github.com/roblox-ts/roblox-ts/pull/2928) but fixes five defects in it locally. The depth and index heuristic broke an _unlabeled_ enclosing loop. `switch` was not counted as a break boundary, and sloptor lowers it to `repeat ... until true`, which a bare `break` exits. Labeled non-loop statements emitted a bare `break`. There was no function or `try` barrier, so a check inside a closure would break the wrong loop. Only the first of two labels on one loop got a continue check. sloptor turns these cases down with clear diagnostics instead of wrong output. Labels crossing `try` or `catch` report `noLabeledStatementsWithinTryCatch`, with a message byte-exact with the PR. Unknown labels behind `// @ts-ignore` report `rotorUnknownLabel`. A labeled non-loop statement whose body also holds an unlabeled `break` or `continue` bound to an enclosing loop reports `rotorLabeledStatementFlowControl`. A labeled `continue` targeting a `do` or `while` whose condition needs temporaries reports `rotorLabeledContinueInDoWhile`. Luau forbids `continue` before those locals, and the identical _unlabeled_ gap is an rbxtsc bug that sloptor reproduces for parity. Byte parity holds, because no label program compiles under rbxtsc, so the `testdata/diff` and `testdata/conformance` goldens didn't change. `internal/transformer/labels_test.go` pins this with authored expectations, not rbxtsc-derived ones. The rotor-owned Lune spec `testdata/conformance/rotor/label.spec.ts` adds 21 runtime cases, and the end-to-end fixture `internal/compile/testdata/labels_model` covers the rest.
- [x] **`--!native` type annotations, October 29, 2026. A sloptor extension, with emitted Luau that differs from rbxtsc.** Opt in through `"rbxts": { "nativeTypes": true }` in tsconfig.json or `nativeTypes = true` in rotor.toml. tsconfig wins when both are set. The default is off, where `//!native` files compile exactly like rbxtsc. When enabled, a file whose leading comments include `//!native` now emits Luau parameter and return annotations taken from the TypeScript types. Those types include `number`, `string`, `vector`, and `Vector3`. Table types appear structurally: `{ T }` for arrays, `{ A | B }` for tuples, `{ [K]: V }` for `Map`, `Record`, and index signatures, `{ [K]: true }` for `Set`, and `{ a: number, b: string? }` for anonymous object types, followed into nested members. Luau's native compiler can then specialize those parameters. A named interface or non-generic object type alias is emitted once as a Luau `type Node<K, V> = { ... }`, with readonly dropped, optional members as `T?`, and self references kept. That alias goes at the declaration when the declaration is a top-level statement of the file. Otherwise it is hoisted next to the header, which covers a namespace-, function-, or block-scoped declaration, or one imported from another module. A merged interface emits one alias at its first declaration, with every merged member. String and boolean literal types mirror as Luau singletons: `there: "there"`, `flag: true`, and `true | false` spelled `boolean`. An enum member and a number literal stay `string` or `number`. A top-level parameter keeps its `"a" | "b"` annotation, which Luau's compiler tags `string`, but a boolean literal there stays unannotated like `boolean`. Function types take the form `(key: K, other: T?) -> V`, and `void` returns `()`. A function's own type parameters are declared, as in `local function f<K, V>(`, and nested positions mirror `boolean` and allowlisted Roblox types by name. Top-level parameters are what Luau tags, so their policy is narrower. `boolean`, Roblox types and `Instance`s, class instances, mixed unions, and a bare generic from an _enclosing_ function stay unannotated. An outer generic would be tagged userdata and break the native entry guard on every call. A form that cannot be written out, such as one deeper than four levels or one with two index signatures, falls back to `{ [any]: any }`. Files without the directive are byte-identical to rbxtsc. sloptor never emits a bare `table`, because Luau's compiler would tag it userdata and the native entry guard would break on every call.
- [x] **`luauTypes` full Luau type annotations, October 29, 2026. An experimental sloptor extension whose emitted Luau differs from rbxtsc.** Opt in through `--luauTypes`, through `"rbxts": { "luauTypes": true }` in tsconfig.json, or through `luauTypes = true` in rotor.toml. The command line overrides tsconfig, and tsconfig overrides rotor.toml. It's off by default. Toggling it moves the incremental salt. A project that never opts in keeps a byte-identical manifest. When enabled, one shared TS-to-Luau builder annotates every file at full fidelity. It works from the TypeScript types over a typed Luau syntax tree. The builder spans `internal/transformer/luautypes*.go` and `internal/luau/types.go`, with a renderer that decides parenthesization. Parameters get `a: number`, optional and defaulted `string?`, rest `...: string`, a destructured `_param: { x: number, y: number }`, and `this` as `self`. Returns get `: boolean`, `LuaTuple` packs `(number, string?)`, `()` for void, and `...nil` for a void body with an explicit `return`. A function declares its own generics, as in `function<T>(value: T): T`. The shadow `local c = c :: number` follows a parameter default and a `??`/`||`/`&&` temp. Neither Luau solver refines through rbxtsc's `if c == nil` chain. `TS.async` locals get the type `(n: number) -> Promise<number>`. Other locals read like hand-written Luau. A local with an initializer takes its type from the value. A local with no initializer, or with a written type that differs from its initializer's, such as an upcast, gets an annotation instead. Every top-level interface, type alias, enum, and class emits `type` or `export type` at its declaration. That covers merged interfaces once, generic aliases with trailing defaults, `readonly` as `read`, and `[A, B]` as `{ A | B }`. `Map` and `Set` become `{ [K]: V }` and `{ [K]: true }`. Overloads become `((A) -> B) & ((C) -> D)`, `keyof T` and `T[K]` become `keyof<T>` and `index<T, K>`, and recursion resolves by name when the arguments match. Nested, ambient, imported, and library types appear as hoisted aliases named from the local import name, where `Box as Container` gives `type Container<T>`. A collision with a Luau builtin, a Roblox extern type, or one of the file's type parameters takes `_2`. Classes become a structural instance alias plus a class table initialized on its declaration line, because rbxtsc's `local Foo` plus `do Foo = ... end` types `Foo` as `T?` inside every method. `Foo.new(x: number): Foo` goes through the double cast `(setmetatable({}, Foo) :: any) :: Foo` and `Foo.constructor(self, x) or self`. Methods are dot-form functions with an explicit annotated `self`, since a colon-form `self` is an unrelated inferred table. Inherited and overridden methods keep the `self` of the class that first declared them, which makes `Derived <: Base` hold. Every function re-declares the class generics, and statics take `self: typeof(Foo)`. A string enum becomes `"up" | "down"` plus a `{ read Up: "up", ... }` map, and a numeric enum becomes `number` plus the inverse-indexed table. A generic alias whose body is a mapped, conditional, or template literal type becomes a Luau `type function` over the `types` library. `Partial2<T>` copies the table and makes every property optional. `T extends (infer U)[] ? U : T` distributes over a union, and `` `on${K}` `` keys build a new table. Every parameter gets the annotation `T: type`. The built-in helpers used generically go through a hoisted prelude: `__Partial`, `__Required`, `__Readonly`, `__Pick`, `__Omit`, `__Record`, `__Exclude`, `__Extract`, `__NonNullable`, `__ReturnType`, and `__Parameters`. Closed uses expand exactly from the resolved type. A body the translator can't express falls back to `any` under a `-- luauTypes:` comment. Number literals widen to `number`, template literals to `string`, and tuples to the element union. sloptor records every substitution as a fidelity loss that the tests assert. The output targets Luau's new solver, the only place `keyof<>`, `index<>`, and type functions exist. The `TestLuauTypesFixturesAnalyzeClean` test renders every fixture under `internal/transformer/testdata/luautypes`. It requires `luau-lsp analyze --flag:LuauSolverV2=true` with the stub definitions to pass each one in strict mode with zero type or syntax errors. `TestLuauTypesClassIdiomProbes` pins the exact error lines of the probes that settled the class, enum, and type-function layouts. With the option off every file is byte-identical to before. When both modes are on in a `//!native` file, the native policy annotates the signatures, and `luauTypes` annotates the locals, enums, and aliases. Design record: `docs/superpowers/specs/2026-10-29-luau-types-design.md`
