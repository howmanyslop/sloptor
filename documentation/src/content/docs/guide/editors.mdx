`sloptor lsp` is a language server over stdio. stdio is the only transport.
Editors send `--stdio` for compatibility. The server ignores the flag. It runs
the same [census](/sloptor/guide/diagnostics/) as the diagnostics command over
your unsaved buffers and publishes the result as editor diagnostics with the
source `sloptor`. The [lsp command reference](/sloptor/commands/lsp/) lists its
flags.

It reports what your TypeScript server can't: transformer diagnostics such as
`noAny`, unsupported Luau constructs, macro failures, comment-directive
refusals and internal compiler errors. The editor's own TypeScript server
reports TypeScript errors (`TS####`), so nothing shows up twice. Run it next to
that server, not instead of it.

The server checks immediately on open and save, and 250 ms after you stop
typing. Each check is a full compile of the project.

## Project setup

The server finds a project by walking up from the open file to the nearest
`tsconfig.json`. If `node_modules/@rbxts` isn't beside that config or in a
parent directory, the server ignores the file. It treats the file as outside a
roblox-ts project. There is no setting for the project path. Workspace roots,
`rotor.toml` and environment variables don't take part in finding the project.

The compiler also checks the options in `tsconfig.json`. Set these
`compilerOptions`:

| Option                         | Required value                                                                |
| ------------------------------ | ----------------------------------------------------------------------------- |
| `noLib`                        | `true`                                                                        |
| `strict`                       | `true`                                                                        |
| `module`                       | `commonjs`, or `preserve` with `moduleResolution: bundler`                    |
| `moduleDetection`              | `force`                                                                       |
| `moduleResolution`             | set explicitly to `Node` or `Node10`, or to `bundler` with `module: preserve` |
| `allowSyntheticDefaultImports` | `true`                                                                        |
| `typeRoots`                    | must contain `node_modules/@rbxts`                                            |
| `rootDir` or `rootDirs`        | set one of the two                                                             |
| `outDir`                       | set a path                                                                     |
| `importsNotUsedAsValues`       | omit it, use `verbatimModuleSyntax`                                            |

Every entry in `types` must resolve under one of the `typeRoots`. This config
satisfies the checks:

```json
{
	"compilerOptions": {
		"allowSyntheticDefaultImports": true,
		"module": "commonjs",
		"moduleDetection": "force",
		"moduleResolution": "Node",
		"noLib": true,
		"outDir": "out",
		"rootDir": "src",
		"strict": true,
		"typeRoots": ["node_modules/@rbxts"],
		"types": []
	},
	"include": ["src"]
}
```

The top-level `rbxts` key holds build options, not these compiler options. See
[tsconfig rbxts](/sloptor/configuration/tsconfig/) and
[rotor.toml](/sloptor/configuration/rotor-toml/).

## Settings

The server has one setting: `initializationOptions.typeErrors`, a boolean that
is off by default. With it off, the server drops diagnostics whose code is
`TS####`. Turn it on only for an editor that has no TypeScript server, or those
errors show up twice. `typeErrors` is an initialization option, not a
command-line flag. `sloptor lsp` accepts only `--stdio` and the global flags.

Each editor passes it differently. The snippets below show the default, off
state.

## Neovim

Neovim 0.11 or later:

```lua
vim.lsp.config("sloptor", {
	cmd = { "sloptor", "lsp", "--stdio" },
	filetypes = { "typescript", "typescriptreact" },
	root_markers = { "tsconfig.json" },
	init_options = { typeErrors = false },
})
vim.lsp.enable("sloptor")
```

`cmd` needs the binary on your `PATH`. The npm package installs it as `rotor`,
so npm users need `{ "rotor", "lsp", "--stdio" }` or an absolute path. See
[Install](/sloptor/guide/install/).

## Helix

In `languages.toml`:

```toml
[language-server.sloptor]
command = "sloptor"
args = ["lsp", "--stdio"]
config = { typeErrors = false }

[[language]]
name = "typescript"
language-servers = ["typescript-language-server", "sloptor"]

[[language]]
name = "tsx"
language-servers = ["typescript-language-server", "sloptor"]
```

Keep `typescript-language-server` in the list. `sloptor lsp` reports
transformer diagnostics, and the TypeScript server reports type errors.

## Zed

Zed only launches language servers that an extension registers. The sloptor
repository has one in `editors/zed`. Open the command palette, run
`zed: install dev extension` and select that directory. Zed builds the
extension itself, so it needs a Rust toolchain installed through `rustup`.

The extension looks for `sloptor` on your `PATH` and runs
`sloptor lsp --stdio`. All of these keys are optional in Zed's
`settings.json`:

```json
{
	"lsp": {
		"sloptor": {
			"binary": { "path": "/path/to/sloptor" },
			"initialization_options": { "typeErrors": false }
		}
	}
}
```

`binary.path` replaces the `PATH` lookup. Use it when the executable isn't on
your `PATH`, as with an npm install. `binary.arguments` replaces the default
`["lsp", "--stdio"]`. `initialization_options` passes through to the server.

To turn the server off for one language, add `"!sloptor"` to that language's
`language_servers` array.

## Other editors

VS Code only launches language servers that an extension registers, and
sloptor has no extension yet. Run
[`sloptor diagnostics`](/sloptor/commands/diagnostics/) from the terminal for
the same checks.

## Troubleshooting

### Tsconfig validation errors

The editor shows two notifications. One contains
`compile: invalid tsconfig.json configuration`. The other contains the
compiler's validation text:

```
Invalid "tsconfig.json" configuration!
https://roblox-ts.com/docs/quick-start#project-folder-setup

- "rootDir" or "rootDirs" must be defined
- "outDir" must be defined
```

Neither is a language server setting. Both come from the compiler rejecting
the project's `tsconfig.json`. The server forwards census errors and
project-level diagnostics through `window/showMessage`, so these are
notifications rather than diagnostics on a line. It shows each error once, and
repeats it only after a census in which the error was absent. A broken config
doesn't raise a popup per keystroke.

Add `rootDir` or `rootDirs` and `outDir` to `compilerOptions`, then check the
rest of the list in [Project setup](#project-setup). Only the missing options
appear in the message, so fixing these two can uncover another. Save the file
to run a new census. The same validation applies to
[`sloptor build`](/sloptor/commands/build/) and
[`sloptor check`](/sloptor/commands/check/).

### No diagnostics appear

The server ignores a file when it can't find a `tsconfig.json` above it, or
when `node_modules/@rbxts` is absent beside that config and its parents. Both
failures are silent. Open a file inside the project, install its `@rbxts`
packages, and check that the nearest `tsconfig.json` is the one you expect. A
plain TypeScript project has no sloptor diagnostics by design.

If the server doesn't start at all, check the binary name on your `PATH` and
the editor's language server log. The server writes its protocol to stdout and
everything else to stderr.
