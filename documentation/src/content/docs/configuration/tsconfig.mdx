Build options can live under the top-level `"rbxts"` key of `tsconfig.json` instead of the command line. The merge order is defaults, then `rbxts`, then command-line flags.

The `rbxts` values merge through the `extends` chain from parent to child, path values resolve relative to the file that declares them, and command-line values win over tsconfig values. CLI-only values such as `watch`, `verbose`, and `usePolling` are warned about and ignored when placed under `rbxts`.

`nativeTypes` has a second surface: the top-level `nativeTypes` key in `rotor.toml`. The tsconfig value wins whenever it is declared (including an explicit `false`); otherwise the `rotor.toml` value applies, and both unset means off.

## Source maps

Enable `compilerOptions.sourceMap` to write a `.luau.map` beside each Luau output:

```json
{
	"compilerOptions": {
		"sourceMap": true
	}
}
```

Source maps provide an anchor at generated column 0 on each mapped Luau line, plus segments where expressions, object fields, and source operators begin. Arithmetic, comparison, concatenation, logical, compound-assignment, and optional-chain operators point to their TypeScript tokens, including tokens on continuation lines. Generated and original columns use UTF-16 code units.

Binding names in declarations and parameters, punctuation, and synthesized literals do not receive their own segments. Compiler headers stay unmapped, and the maps have no `names` field. Maps describe the unminified output, so positions in output produced with `--minify` do not match them. Expression origins are collected only when source maps are enabled.

## Editor schema

The `rotor.toml` schema and the tsconfig `rbxts` schema are separate documents. Publish the `rbxts` one where your editors can read it:

```sh
sloptor schema --rbxts > rbxts-tsconfig.schema.json
```

Then point `tsconfig.json` at it:

```json
{
	"$schema": "./rbxts-tsconfig.schema.json",
	"rbxts": {
		"type": "game",
		"optimizedLoops": true
	}
}
```
